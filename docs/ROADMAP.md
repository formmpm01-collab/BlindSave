# Siguientes fases

La primera entrega es una vertical funcional de electricidad. Para dar el servicio con datos reales falta conectar un proyecto Supabase, publicar ofertas verificadas, desplegar el frontend y configurar operación/retención.

1. **Catálogo de mercado:** ingesta Python de fuentes públicas autorizadas, extracción estructurada con evidencia y unidades, huellas de documentos, detección de cambios y revisión humana de borradores. Publicar solo tras verificación; programar refresco diario y retirar ofertas caducadas.
2. **CSV de distribuidoras:** adaptadores locales por formato real, tests con muestras anonimizadas, horas 1–24, periodos explícitos y variantes DST. No aceptar columnas identificativas por simple omisión silenciosa sin revisar el flujo de privacidad.
3. **Asistente de condiciones:** retrieval de documentos públicos, embeddings con modelo versionado, respuesta citada y abstención ante evidencia insuficiente. No enviar consumos ni identificar usuarios en consultas al modelo.
4. **Más modalidades eléctricas:** perfiles horarios completos para PVPC/indexadas, fuentes históricas verificadas, promociones por periodos, fiscalidad por fecha/territorio y supuestos visibles. No mezclar estos productos con el motor de precio fijo actual.
5. **Telecomunicaciones y gas:** esquemas y motores propios para líneas/GB/velocidad/permanencia y RL.1–RL.3/TUR. Revisar el coste total fuera de promoción.
6. **Suscripciones:** comenzar por selección de catálogo y valores manuales. Excluir CSV bancarios hasta disponer de una frontera de privacidad local probada con formatos reales.
7. **Guardado opcional:** consentimiento explícito, conversión de sesión anónima en cuenta, RLS por propietario, exportación/borrado, retención y recuperación. No guardar histórico por defecto.

Una buena demostración grabada de esta fase: modo demo visible → datos de ejemplo o CSV sintético → ranking y desglose → condiciones → privacidad → borrar datos. Identificar claramente que los precios son ilustrativos.
